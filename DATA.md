# Data format

Every dataset is **standard GeoJSON** ([RFC 7946](https://datatracker.ietf.org/doc/html/rfc7946)) plus one small description file. The app makes no external requests; all files live in `public/data/` and are listed in `public/data/manifest.json`.

```
public/data/
  manifest.json            datasets shown in the picker (status "ready" or "planned")
  <id>.json                description: fields, levels, measures, attribution
  <id>/features.geojson    Points or (Multi)Polygons with numeric properties
  <id>/flows.geojson       optional LineStrings with origin, destination, volume
```

## Features: `FeatureCollection` of Points or Polygons

- `id` (string): unique, used to join flows and parents.
- `properties.name`: label shown in tooltips.
- Every name listed in the description's `fields` is a numeric property. `null` or missing means no data, never zero.
- Parent keys for coarser levels are properties too (e.g. `"state": "06"`).

```json
{"type": "Feature", "id": "220",
 "geometry": {"type": "Point", "coordinates": [5.35199, 60.37969]},
 "properties": {"name": "Møllendalsplass", "starts": 1234, "ends": 1180, "durationMin": 9876.5}}
```

## Flows: `FeatureCollection` of LineStrings (optional)

One feature per origin → destination pair; `properties.origin` and `properties.destination` are feature ids, and the property named by `flowField` (default `trips`) is the volume. The line geometry is the straight connection, so the file is viewable in any GIS; the app re-routes flows at coarser levels. Round trips may be included with origin = destination (a two-point line at one position); they count for nodes but draw no line.

**Time (optional).** A property named by `time.slots` holds rows `[slot, …time.slotFields]` with `slot = weekday × 24 + hour` (weekday 0 = Monday), e.g. `"slots": [[8, 10, 52.5], [134, 3, 30.0]]` = 10 trips (52.5 min) on Monday 08–09 and 3 on Saturday 14–15. With slots present the Time filter (days, hours) becomes available, and feature fields listed in `flowDerived` are recomputed from the filtered flows.

```json
{"type": "Feature", "id": "220>5",
 "geometry": {"type": "LineString", "coordinates": [[5.35199, 60.37969], [5.33572, 60.37712]]},
 "properties": {"origin": "220", "destination": "5", "trips": 42}}
```

## Description file `<id>.json`

| Key | Meaning |
| --- | --- |
| `geometry` | `"points"` or `"areas"` |
| `region` | projection set: `us`, `bergen`, `israel` |
| `features`, `flows`, `flowField` | GeoJSON paths (relative to `public/data/`) and the flow volume property |
| `fields` | numeric feature properties used by measures |
| `levels` | finest first. Coarser levels group by a `parent` property (optionally with a `features` GeoJSON of their polygons) or snap points to a `cluster` grid in metres |
| `measures` | `kind`: `count`, `signed`, `ratio` (`num` / `den`), `median` (`field`, optional `weight`), `category` (`parts`) |
| `time` | `{slots, slotFields, basis}`: flows carry weekday-hour slots (enables the Time filter) |
| `flowDerived` | feature fields recomputed from filtered flows: `out:`, `in:`, `self:` or `net:` + a slot field, e.g. `"starts": "out:trips"` |
| `unavailable` | controls this dataset turns off, keyed `control:value` (e.g. `"variant:noncontiguous"`), with the reason students see |
| `base`, `outline` | optional GeoJSON for context/clipping (e.g. land) and for borders drawn over choropleths |
| `source`, `attribution`, `note` | shown in the footer |

Polygons may be wound either way: the loader rewinds RFC 7946 counter-clockwise rings for d3. Our scripts write RFC 7946 winding.

## Datasets

The bundled files are static snapshots; they were prepared once and are not regenerated by the build.

### US counties · ACS 2022 (`acs`)
2022 American Community Survey 5-year estimates (U.S. Census Bureau, public domain): population, median household income, White alone, Black alone, Asian alone, Hispanic/Latino. Boundaries are the us-atlas county and state polygons (Census cartographic boundaries), stored as RFC 7946 GeoJSON with coordinates rounded to 4 decimals. Connecticut planning regions and the split Alaska census areas in the 2022 ACS postdate those boundaries and show no data.

### Bergen Bysykkel · trips (`bergen`)
Source: <https://bergenbysykkel.no/en/open-data/historical>, July 2026 (`https://data.urbansharing.com/bergenbysykkel.no/trips/v1/2026/07.json`), licensed under the Norwegian Licence for Open Government Data (NLOD) 2.0. 20,473 trips, 98 stations, 4,972 origin–destination pairs including round trips. Station positions are medians of the reported coordinates; slots use the trip start in Europe/Oslo local time. Measures: trip starts, trip ends, net departures, mean trip duration, round-trip share; all follow the Time filter. Levels: station, 300 m cluster, 1 km cluster. Defaults: Mercator projection with the OSM basemap.

### Adding a dataset
Write the GeoJSON files and a description file in the format above, put them in `public/data/`, and add an entry with `"status": "ready"` to `manifest.json`.
